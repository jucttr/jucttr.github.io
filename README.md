## AGENTS.md 编写与维护

仓库根目录的 [AGENTS.md](AGENTS.md) 供 AI 编码工具在会话启动时自动读取。它不是给访客看的项目说明，而是给编码工具看的操作约定，已按「红线、命令、路由」三层组织。本节说明这个文件解决什么问题、什么情况下值得维护，以及增删规则的标准。

### 适用条件

| 情况                                       | 是否需要                     |
| ------------------------------------------ | ---------------------------- |
| 项目由多种 AI 编码工具协作维护             | 需要，一份文件多家通用       |
| 构建、测试和格式命令无法从配置文件直接看出 | 需要，避免工具反复猜错       |
| 存在代码里读不出来的红线与历史约束         | 需要，例如版本上限与临时覆盖 |
| 只用一种工具、命令也都写在 `package.json`  | 可以只写该工具自己的记忆文件 |
| 一次性脚本或个人临时分支                   | 不必，指令写在当次任务里即可 |

判断标准是「不可推断」：读代码和配置就能知道的事不必写进去，只有猜不出来、且猜错会造成返工或破坏的内容才值得常驻。

### 编写标准

一条规则要不要留下，依次问四句：

| 判断                       | 结论                       |
| -------------------------- | -------------------------- |
| 它自己能推断出来吗？       | 能则不写，纯占上下文       |
| 删掉它会改变行为吗？       | 不会则不写，属于无效规则   |
| 能用命令或钩子自动检查吗？ | 能则交给命令、lint 或 CI   |
| 每个任务都要遵守吗？       | 是则放根目录，否则放子目录 |

写法上遵循四条：

- **反向意图优先。** 「不要把 TypeScript 升到 7」比「保持依赖兼容」更能改变行为，前者能指认具体事故，后者是空话。
- **给判据，不给步骤。** 写「`pnpm format:check && pnpm build` 全绿」，而不是「先格式化，再检查类型，然后构建」，让工具自己安排路径。
- **事故驱动。** 从空文件开始，见到它真的犯错再补一条；不要一次性生成长篇说明，过时的指令比没有指令更糟。
- **控制篇幅。** 根文件保持在百行量级，内容越长，靠后的规则越容易被忽略；能用命令、CI 或钩子兜住的，就不写成自然语言。

文件只提供软约束，不能替代硬保障：真正不可回退的操作要靠 Git 钩子、CI 和代码审查拦住，不能指望一段文字。

### 与其他文件的关系

| 文件               | 读者         | 内容                                         |
| ------------------ | ------------ | -------------------------------------------- |
| `README_backup.md` | 人           | 项目说明、写作方式、部署与测试               |
| `AGENTS.md`        | 各类 AI 工具 | 红线、命令入口，以及「去哪里读细节」的路由   |
| `CLAUDE.md`        | Claude Code  | 仅它支持的特性，用 `@AGENTS.md` 引入通用部分 |

`AGENTS.md` 是开放格式，被 Codex、Cursor、Copilot、Devin 等工具共同读取；Claude Code 默认只读 `CLAUDE.md`。若在本项目使用 Claude Code，需要新建 `CLAUDE.md` 并写入 `@AGENTS.md`，否则仓库里的约定不会被加载。

### 维护方式

- 每次发现工具犯同一个错，就在红线里补一条，注明防的是哪次问题。
- 依赖、命令或目录变更后同步更新；过时的指令会让工具自信地做错。
- 定期修剪：删掉已经能从代码推断出来的规则，把长说明下沉到子文件，并在路由表里写明「什么情况下去读」。
- 不要把密钥、真实域名凭据等敏感值写进去，文件会随仓库提交。
